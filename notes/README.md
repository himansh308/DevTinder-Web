# DevTinder Frontend Learning Notes

Personal study notes from building the DevTinder frontend (React + Vite, Tailwind/DaisyUI,
React Router, Redux Toolkit, Axios/CORS auth wiring) — same spirit as the backend's `notes/`
folder: real code, real bugs actually hit, explained the way they were worked through live.

- [react-router-patterns.md](./react-router-patterns.md) — `BrowserRouter`, nested `<Routes>`/`<Route>`, `<Outlet/>` layout pattern, `useNavigate` vs the `<Navigate>` component.
- [redux-toolkit-basics.md](./redux-toolkit-basics.md) — `createSlice`, `configureStore`, default vs. named exports (why `userReducer` and `userSlice.reducer` are "the same thing, different name"), how the `reducer` key shapes the global state tree.
- [cors-and-cookies.md](./cors-and-cookies.md) — CORS `credentials`, `withCredentials`, and the cookie-scoping mix-up that looked like a bug but was a stale-cookie false alarm.
- [tailwind-daisyui-setup.md](./tailwind-daisyui-setup.md) — why versions were pinned (v3/v4, not latest), the `<Div>`/self-closing `<input>` crashes, and the VS Code autocomplete-in-strings setting.
- [javascript-gotchas.md](./javascript-gotchas.md) — converting a controlled numeric input's value on every keystroke (`Number(e.target.value)`) breaks clearing/retyping the field; convert once, at the point of actual use instead.
- [react-controlled-inputs.md](./react-controlled-inputs.md) — the `checked` prop mental model built up from a plain boolean to an array (`genderPreference.includes(...)`), and why a checkbox representing one array member toggles via `.filter()`/spread instead of `e.target.value`.
- [browser-apis-geolocation.md](./browser-apis-geolocation.md) — `navigator.geolocation` as a built-in browser global (no import needed), its callback-style (not Promise-based) API, the GeoJSON longitude-first vs. latitude-first-named gotcha, and why `error.code` distinguishes an unrecoverable denial from a retryable failure.
- [debounce-and-rate-limiting.md](./debounce-and-rate-limiting.md) — debounce vs. throttle for search-as-you-type, why the debounce delay itself must be ≥ a real rate limit's interval to guarantee compliance, the `useEffect`+`setTimeout`+cleanup mechanism, and the `useRef` guard against stale out-of-order responses.
- [location-feature-end-to-end.md](./location-feature-end-to-end.md) — **start here for location.** The whole feature in one place, frontend + backend: auto GPS on visit, manual search, sticky override. Real Nominatim outputs, how the permission popup and `position` actually flow, the "photo vs whiteboard" stale-reply guard, what `locationAutoSync: selectedLocation.autoSync` means, every design decision, and known issues.
- [session-2026-09-12-13-frontend-setup.md](./session-2026-09-12-13-frontend-setup.md) — chronological log of every bug hit while scaffolding the frontend and wiring up the first Login flow.
- [session-2026-09-22-23-feed-and-route-protection.md](./session-2026-09-22-23-feed-and-route-protection.md) — route protection, logout, feed fetch/render, `UserCard`, single-card-at-a-time swipe logic — 24 bugs/confusions logged, including the recurring "missing `return` in a block-body arrow function" and "calling a handler immediately instead of passing a reference" patterns.
- [session-2026-09-24-editprofile-bugs-and-login-race.md](./session-2026-09-24-editprofile-bugs-and-login-race.md) — `EditProfile` null-guard + `useState`-only-initializes-once bugs, `UserCard`'s buttons leaking into the preview, a login-guard race condition fixed by switching from effect-based `navigate()` to a render-time `<Navigate>`, and the Wikipedia-page-vs-direct-image-URL mixup.
